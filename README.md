# ძირკვა (dzirkva)

ქართული საძიებო სისტემა. აჩვენებს მხოლოდ ქართულ გვერდებს და ეძებს იმას, რაც ადამიანმა დაწერა: ბლოგებს,
სამეცნიერო ნაშრომებს, ვიკიპედიის წყაროებს, დახურული საიტების ძველ ასლებს.

ძიების დროს ენის დიდი მოდელი არ მუშაობს. მუშაობს მხოლოდ კოდი და ერთი ლოკალური მოდელი, BGE-M3.

ცოცხალი ვერსია: https://dzirkva.ge

## როგორ ეძებს

1. შეკითხვას ასწორებს: ლათინური ასოები ქართულად (`kartuli` → `ქართული`), მართლწერა, სიტყვის ფორმა ლექსიკონის
   ფორმად (`morph.py` და ka-lemma-ს ცხრილი `data/families.db`).
2. ერთდროულად ეკითხება Brave-ს (ერთი ფასიანი გამოძახება ძიებაზე) და საკუთარ ინდექსებს.
3. შედეგებს ალაგებს საძიებო სისტემის ადგილით, აზრით (BGE-M3), წყაროს სანდოობით და იმით, შეკითხვის რამდენი
   სიტყვაა ტექსტში. ყოველი შედეგის ქვეშ წერია, რატომ დადგა იქ.

კოდი: `src/dzirkva/search.py`. ტერმინალში: `uv run python -m dzirkva.search ქართული ანბანი`.

## ინდექსები

ყველა ფაილი `data/`-შია და git-ში არ შედის.

| ფაილი | რა არის |
|---|---|
| `wiki.db`, `wikisource.db` | ქართული ვიკიპედია და ვიკიწყარო |
| `crawl.db` | საკუთარი ქრაული: სანდო საიტები და იშვიათი ქართული საიტები |
| `passages.db` | ~870 ათასი აბზაცი BGE-M3 ვექტორით (ვიკიპედია, ნაშრომები, ივერიელი) |
| `papers.db`, `iverieli.db` | სამეცნიერო ნაშრომები (OAI-PMH) და ეროვნული ბიბლიოთეკის კატალოგი |
| `archive.db` | დახურული ქართული საიტების ასლები Internet Archive-დან |
| `families.db` | 1.65 მლნ სიტყვის ფორმა → ლექსიკონის ფორმა (ka-lemma პროექტიდან) |
| `dictionary.db` | ვიქსიკონის განმარტებები |

სანდო საიტების სია: `config/sources.yaml`.

## გაშვება

საჭიროა Python 3.12 და [uv](https://docs.astral.sh/uv/).

```bash
uv sync
uv run python -m dzirkva.web
```

გვერდი გაიხსნება http://127.0.0.1:8000-ზე. `.env`-ში უნდა იყოს `BRAVE_API_KEY` და `SEARXNG_SECRET`
(ნებისმიერი გრძელი სტრიქონი; მისით იწერება `/go` ბმულები). BGE-M3 პირველ გაშვებაზე ~2 GB-ს ჩამოტვირთავს.

`.env`-ის სხვა ცვლადები:

| ცვლადი | ნაგულისხმევი | |
|---|---|---|
| `BRAVE_DAILY_LIMIT`, `BRAVE_MONTHLY_LIMIT` | 20, 300 | Brave-ის გამოძახებები; `0` გამორთავს |
| `MAX_SEARCHES` | 3 | ერთდროული ძიებები |
| `MEANING_WEB` | 1 | `0`: ნელ CPU-ზე ახალი ვექტორები არ ითვლება |
| `SEARXNG` | 0 | `1`: Yandex და Yahoo SearXNG-ით |
| `STATS_KEY` | | `/stats` სხვა კომპიუტერიდან |

## სერვერი

ძირკვა მუშაობს სახლის სერვერზე (Ubuntu, 7 GB RAM, GPU არ აქვს), Cloudflare Tunnel-ით. systemd-ის ფაილები
`config/systemd/`-შია:

- `dzirkva-web`: საძიებო გვერდი;
- `dzirkva-crawl`: ქრაულერი, რომელიც სულ ნელა მუშაობს (ერთი ბირთვის მეოთხედი, 1.2 GB) და ახალ გვერდებს თვითონ
  ამატებს;
- `searxng`: გამორთულია.

კოდის განახლება: `git ls-files -z | rsync -t --files-from=- --from0 . rexvopc:dzirkva/`, შემდეგ ვებ-სერვისის
გადატვირთვა.

## მონაცემების აგება

ყოველი სკრიპტის თავში წერია, რა სჭირდება და რამდენ ხანს მუშაობს. რიგი:

1. `scripts/build_words.py`, `build_lexicon.py`, `build_wiki_index.py`, `build_dictionary.py`, `build_titles.py`,
   `build_vocab.py`: ენა და ვიკიპედია.
2. `scripts/build_sites.py`, `cc_hosts.py`, `crawl_sites.py`, `score_small_web.py`, `feeds.py`,
   `archive_collect.py`: საიტები.
3. `scripts/build_passages.py`: აბზაცების ვექტორები.

ივერიელისა და ნაშრომების შემგროვებლები `scripts/archive/`-შია: ისინი აღარ მუშაობენ, მაგრამ მათი მონაცემები
ძიებაში რჩება.

## კონფიდენციალურობა

IP მისამართი არ ინახება. ერთ ვიზიტს აკავშირებს შემთხვევითი ქუქი, რომელიც 30 წუთში ქრება; Do Not Track-ის ან
GPC-ის დროს ქუქი არ იქმნება. ჩანაწერები (`data/telemetry.db`) 180 დღეში იშლება.
